# 价格计算方法

本文说明查询页如何调用计价引擎。金额仍由服务配置和已核验样本决定，不由模型生成。

## 评估日 `asOf`

`calculatePrice` 只在调用方传入 `data.asOf` 时做两件事：

- 排除 `collectedAt` 晚于该日期的样本（字符串按 `YYYY-MM-DD` 比较）
- 把该日期交给可信度规则。样本全部早于评估日超过 365 天时，加入警告「价格数据可能已经过时」，并且可信度不会评为「高」

365 天按两个 ISO 日期的 UTC 午夜之差计算，与浏览器时区无关。省略 `asOf` 时不排除样本，也不做这项时效判断，因此「高」可信度不会出现。

计价函数不调用 `Date.now()`、`new Date()` 或上海日历函数。相同服务、答案、地区、价格数据和 `asOf` 得到相同结果。

### 查询页选定的规则

页面打开时在浏览器里确定一次评估日，本次浏览中的再次计算都沿用它：

1. 分享链接里的 `asOf` 能通过 ISO 日期校验时，使用该日期。稍后再次打开同一条链接，时效判断保持不变。
2. 没有合法 `asOf` 时，使用**打开页面这一刻**的上海日历日，而不是点击按钮的时刻，也不是构建网站的日期。

上海没有夏令时。日历日的计算方法是：取该时刻的 UTC 时间戳，加上 8 小时，再读取 UTC 年月日，格式为 `YYYY-MM-DD`。实现位于 `lib/time/shanghai-date.ts`。

因此：

- 同一天、同一条没有日期的链接，评估日相同。
- 过了午夜再次打开没有日期的链接，评估日改为新的一天。这是时效规则，不是同一输入下的随机价格。
- 已经带有合法 `asOf` 的分享链接不随打开时间变化。

静态导出（`output: "export"`）只生成不带查询结果的页面。评估日不在构建时写入 HTML，构建可以重复。浏览器加载页面后再计算。

## 分享链接

查询参数由 `lib/share/query.ts` 生成和解析：

```text
?city=beijing&asOf=2026-11-20&a.lamp-type=ceiling&a.quantity=2&a.remove-old=false
```

- `city` 只能恢复选择器里的城市，或「我的城市不在列表中」所对应的全国记录。
- 省份、城市等级、未知 ID、无法解析的日期、不符合题目校验的答案都会被丢掉，页面继续显示可操作的查询，而不是抛出异常。
- 多选答案重复使用同一个 `a.<问题 ID>`。布尔值写成 `true` 或 `false`。

参数齐备且合法时，页面直接重新计算并显示结果。

## 常见价格

有匹配样本时，`typical` 是这些样本 `price` 的中位数，单位为人民币元：

- 样本个数为奇数时，取排序后正中间的金额。
- 个数为偶数时，取中间两个金额的平均值，并按「.5 向上」四舍五入到整数元。

它不使用语言模型，也不在样本数为 0 时填一个数字。样本数为 0 时结果是 `insufficient_data`，没有 `typical` 和价格区间。常见价格可能与规则算出的参考区间不同：区间解释的是当前选项下的计价规则，常见价格解释的是已匹配样本。

## 哪些因素会影响价格

结果页的升高和降低说明来自 `lib/pricing/factors.ts`。它只读取当前服务的问题、选项附加费、计价附加项和地区规则，不识别具体服务名称。

- 同一道选择题里，费用更高的选项记为升高，费用最低的选项记为降低。费用看附加项的金额上限；百分比单独比较。
- 某个选项会显出一道按量计费的题目时，这项按量费用算到该选项上。
- 无法归到单个选项、但带有条件的附加项，按条件原文说明何时升高，并给出不满足条件时不增加该项。
- 基础价按用量计算时，说明用量越高参考价格越高。
- 地区系数大于 1，或地区基础价区间之和高于服务基础价时，记为升高；小于时记为降低。

文案只说明方向，不另造一套成交价。

## 地区选择与回退

选择器使用 `lib/region/choices.ts`：

- 列出 `level === "city"` 的地区，名称使用地区数据里的 `name`。
- 若存在全国记录，最后追加一项「我的城市不在列表中（全国参考）」，提交该全国记录的 ID。
- 不把省份、城市等级或名为「全国」的记录当成普通选项。

`lib/region/resolve.ts` 保持原有回退：用户选中的城市若没有可用样本，依次尝试所属省、城市等级和全国。直接选择「城市未列出」时，请求的就是全国记录，因此只使用全国样本。
