# 计价方法

PriceRight 给出的是指定服务、指定条件和指定地区下的**合理参考价格**。它是市场参考，不是保证成交价，也不是平台收费标准。

同一服务配置、同一答案、同一地区、同一份价格数据和同一个 `asOf`，必须得到同一个 `PriceResult`。计算由 `calculatePrice(service, input, regionId, data)` 完成。它是纯函数：不读当前时间，不使用随机数，不访问网络，不调用 LLM，也不根据用户身份改价。

LLM 可以协助起草配置或整理公开资料，但不能直接决定价格。正式规则和样本都要经过人工审核后才能进入 `data/`。

## 样本与规则分离

价格规则和服务配置在一起，描述如何从答案得到区间。价格样本单独存放，描述某时某地、在一组条件下观察到的金额、来源和核验状态。

引擎**不用**样本金额求平均、中位数或分位数，也不会把某一条样本的 `price` 直接变成报价。样本只决定三件事：

- 这一级地区有没有资格给出参考价
- 结果采用哪一条地区链上的规则
- 价格构成之外要披露的依据：来源等级、样本数、最近采集日期和可信度

区间来自命中地区的价格规则。该地区没有专用规则时，使用服务的基础规则。只有规则、没有任何合格样本时，结果是数据不足。已经有合格样本时，区间仍来自 `basePrice` 或该地区的 `priceOverride`；样本金额不会被汇总，也不会反过来改写规则。

## 合格样本

参与计算的样本必须同时满足：

- `verified` 为 true
- `demo` 与服务的 `demo` 相同
- `serviceId` 与服务相同
- 提供了 `asOf` 时，`collectedAt` 不晚于该日期
- `conditions` 里的每一项都与当前有效答案一致

条件为空表示不限制答案。多选答案按集合比较：元素相同即可，顺序不要求相同，数量必须相同。样本没写到的问题不参与比较。

隐藏题的答案不会进入后续条件与计价。可见题校验失败时，整个调用返回 `invalid_input`，不会带着残缺答案继续算价。服务状态不是 `active` 时，即使样本合格，也不给出参考价。

## 地区回退

地区级别为 `city`、`province`、`city_tier`、`national`。城市可以带 `parentId`（所属省份）和 `tier`（`tier_1`、`new_tier_1`、`tier_2`、`other`）。

用户选择的是城市时，候选顺序是：

```text
城市 → 省级 → 城市等级 → 全国
```

只把实际存在的下一级放进候选。城市没有 `parentId` 或找不到对应省份时，跳过省级。没有相同 `tier` 的城市等级记录时，跳过城市等级。没有全国记录时，到此为止。

用户直接选择省、城市等级或全国时，不再反向查找城市。省和城市等级之后只再看全国；选择全国时只使用全国。

从前往后采用**第一个至少有一条合格样本**的地区。样本不会跨级混合。一条合格样本就停在该级，即使条数还没有达到 `minimumSampleCount`。城市已有合格样本时，不会改用城市等级或全国规则。

规则也取这一级：只查找 `regionId` 等于命中地区的 `regionRules`。城市规则不会在回退到省份之后继续生效。

结果中的 `assumptions` 使用固定句子：命中用户所选地区时为「使用{地区名}数据」；用了更粗的一级时为「本地数据不足，使用{地区名}参考数据」。

未知 `regionId` 返回 `invalid_input`，提示「请选择有效地区」，不产生区间。

## 区间如何算出

金额是非负整数人民币元（CNY）。Schema 要求每段区间 `min <= max`。引擎不用浮点累加金额。加法是已取整整数的精确相加；乘法（数量、面积、距离、百分比、地区系数）按十进制四舍五入到元，`.5` 进位。

命中地区有 `priceOverride` 时，用它替换基础单价，明细标签为「{地区名}基础价格」。否则使用 `basePrice`，标签为「基础价格」。这行的 `operation` 是 `add`。

配置了 `unitQuestionId` 时，基础单价乘以该题的非负数值，并用乘积**替换**累计区间。题型是 `area` 或 `distance` 时，明细来源用对应类型；其余用量题用来源 `quantity`。按小时计价绑定的也是数值题，所以来源同样是 `quantity`。标签是「{问题标题} × {数值}」。用量不合法，或金额超出安全整数时，返回 `invalid_input`，不给出失真金额。

然后按固定顺序收取附加费：先是服务级 `modifiers`，再按问题顺序加入已选选项上的 `priceModifier`。选项是否选中，单值看相等，多选看是否包含该选项的 `value`。附加费自己的 `conditions` 必须全部成立。

- `fixed`：把该区间加到累计值上
- `per_unit`：绑定题出现在有效答案里才计算，区间乘以该题用量后加到累计值上。题目被隐藏或选填未答时跳过
- `percentage`：先固定当前小计，再用这个**同一小计**乘以百分数（`value` 为百分数，10 表示 10%）后相加。几条百分比互不叠乘

地区规则里的 `multiplier` 在附加费之后作用于累计区间，并替换累计值。明细标签为「{地区名}系数 × {系数}」。

最后才应用 `minimumPrice`。仅当累计下限低于它时，把累计区间替换为下限等于最低收费、上限不低于最低收费的区间。标签为「最低收费」。

`model` 约束规则能否绑定用量：`fixed` 与 `range` 不绑定数量，且 `fixed` 的基础下限必须等于上限；`per_unit`、`hourly`、`area`、`distance` 必须绑定用量。真正乘用量的是 `unitQuestionId`，不是模型名称本身。

## 价格构成

`estimated` 必须带回 `breakdown`。每一行有 `label`、`source`、`operation` 和本行 `range`。

- `add`：本行金额加到前面的累计值上
- `replace`：本行金额是调整之后的累计区间

从 0 开始按这个规则重放每一行，得到的区间就是 `range`。结果页把 `replace` 标为「调整后小计」，标题使用「价格构成」。

`source` 只可能是 `base`、`modifier`、`quantity`、`area`、`distance`、`region`、`minimum`。

## 三种结果

| 状态 | 含义 |
| --- | --- |
| `estimated` | 有合格样本。返回区间、价格构成、实际采用的地区、来源、样本数、最近采集日期、可信度和警告 |
| `insufficient_data` | 没有可用参考价。`range` 为 null，样本数为 0，可信度为 `low` |
| `invalid_input` | 答案不完整、计量值非法、地区不存在，或 `asOf` 不是 `YYYY-MM-DD` |

正式数据的 `estimated` 在页面上写「合理参考价格」。演示数据写「演示价格区间」，并标明合成数据，不能当作实际询价依据。

数据不足时的警告原文是：

```text
目前暂无足够的可用价格数据，暂不能提供可靠参考价格。
```

页面标题为「数据不足」。这种结果不带价格区间。出现它的情况包括：整条地区链都没有合格样本、样本全部晚于 `asOf`、条件对不上、样本未核验、数据集的 `demo` 标记不一致，或服务不是 `active`。

样本数大于 0 但少于 `minimumSampleCount` 时，**仍然**返回 `estimated`。默认门槛是 5，服务可以在 `pricing.minimumSampleCount` 里修改。同时给出警告「数据样本有限，结果仅供粗略参考」，可信度为低。这和一条样本都没有时的数据不足是两件事。

## 可信度

来源等级由 `sampleType` 决定，并随结果披露：

| 样本类型 | 等级 | 含义 |
| --- | --- | --- |
| `actual_transaction` | A | 实际成交 |
| `provider_quote` | B | 服务商公开报价 |
| `public_price` | C | 公开平台报价 |
| `manual_reference` | D | 人工整理参考 |

页面把 `high`、`medium_high`、`medium`、`low` 显示为高、较高、一般、低。分级使用全部命中样本，初始规则如下，尚待真实数据检验。

默认是低。同时满足「不是演示样本、条数达到门槛、没有过时、地区不是城市等级或全国」时，升为一般。在此之上，地区是城市，且实际成交和服务商报价合计达到门槛，升为较高。再同时满足「调用方传入了 `asOf`、相对该日期 365 天内的样本达到三倍门槛、其中至少有一条实际成交」时，升为高。较高看的是全部命中样本里的成交和报价条数；高看的是 365 天窗口内的条数。窗口内和窗口外的样本同时存在、且并未全部过时时，较早的成交和报价仍计入「较高」的条数。

因此：

- 公开平台报价和人工整理参考，在城市或省样本足够时可以是一般，不能单靠这两类升到较高
- 省可以到一般，不能到较高或高
- 城市等级和全国保持低，即使样本很多
- 任一演示样本都会使可信度保持低，并附加警告「demo 测试数据，仅用于验证计算」
- 未传入 `asOf` 时不做过时判断，最高只能到较高

`dataUpdatedAt` 是所采用样本里最晚的 `collectedAt`。

## `asOf`、过时与尚未采集的样本

`asOf` 是调用方传入的评估日期，格式为 ISO 日期。引擎不拿本机当天代替它，否则同一输入会随日期变化。

晚于 `asOf` 的样本直接排除。排除后若整条地区链都没有剩余样本，结果是数据不足，而不是一个过时价格。

留下来的样本若全部早于 `asOf` 超过 365 天，仍然用它们计算区间，但警告「价格数据可能已经过时」，可信度保持低。365 天按评估日期与采集日期的 UTC 日历差计算，满 365 天仍算在窗口内。旧样本不会仅仅因为变旧就被删掉。

未传入 `asOf` 时，不排除未来日期，也不提示过时。正式发布若要判断时效，应显式传入评估日期。

## 询价确认清单

`lib/pricing/checklist.ts` 不计算价格。它只读取服务配置、已选条件摘要和已经算好的结果，生成一段纯文本。

附加项是否标成「当前选择已计入」，规则与上面的附加费选取相同：可见且有效的答案、服务级 `modifiers`、被选中选项的 `priceModifier`、附加项自身条件，以及 `per_unit` 必须能读到绑定题目。清单里的金额只转写结果上的区间。`estimated` 且非演示写「合理参考价格」；演示写「演示价格区间」并标明合成数据；`insufficient_data` 不写金额，只写暂无公开参考区间。
